# EBPM 分析のルール

D2PA の EBPM 分析における、問いの立て方・手法の選択基準・主張の強さのルール・統計的誠実性ルールを定める。

背骨は二つ：
1. **最小の分析で政策の問いに答える。**「データ分析のためのデータ分析」は徹底性ではなく失敗である。
2. **案件ではなく、問いを分類する。** 案件を型に押し込まず、問題意識を「問いの束」に分解し、問いごとに手法を選ぶ。

---

## 1. 案件は「問いの束」に分解する

自治体の問題意識は、そのままでは分析できない。分析に先立ち、要件とデータの実態（行数・列・欠損などの監査結果）を踏まえて、問題意識を**次の5つの問いの型**に分解する。1つの案件は通常、複数の型の問いを含む。分析のタスクはこの問い単位で立て、手法は問いの型で引く。

| 型 | 問い | 典型例 |
|----|------|--------|
| **Q1 記述する** | 現状はどうなっているか | 「進学希望の分布は」「満足度の水準は」 |
| **Q2 関連を探る** | 何と何が関係しているか | 「地元愛着と残留意向は関係するか」 |
| **Q3 因果効果を推定する** | 施策は効いたのか／効くのか | 「イベントで来訪者は増えたか」 |
| **Q4 予測・分類する** | どの層がどうなりそうか | 「どんな生徒が県外流出しやすいか」 |
| **Q5 分解・モニタリングする** | 目標をどう分解し進捗をどう測るか | 「KPI◯◯を構成要素に分解せよ」 |

この5型は、統計学で標準的なデータ分析の3タスク分類（記述・予測・因果推論）を基礎に、実務で頻出する細分（関連の探索、分解・モニタリング）を加えたもの。案件の来かた（アンケート・効果検証・計画策定など）がどうであれ、手法の選択はこの問いの型で引く。

**型に落ちない問い**（最適化、シミュレーション、政策オプションの比較考量そのもの等）は、無理に型へ押し込まず「対応範囲外」として正直に報告する（「実行不可能は実行不可能と報告する」原則と同じ）。なお**調査・アンケートの設計支援**は分析の問いではなく、「証拠を強くする次の一手」（2-5節③）として扱う。

---

## 2. 主張の強さは二軸で扱う

主張の強さを一本のダイヤルで上下させない。**「設計が何を支えるか」（軸1）**と**「結果がどれくらい確かか」（軸2）**は別の次元であり、混同が過大主張と過小主張の両方を生む。

### 2-1. 軸1：設計の強さ（causation_claim）

**最重要ルール：識別戦略の裏付けなしに因果の語を使わない。**

因果を語る条件は、識別戦略が設計として成立し、その中核的な仮定が確認できる（もしくは妥当と判断できる）ことである。データが実験由来か観察由来かということ自体は条件ではない——観察データでも識別の裏付けがあれば因果を語りうるし、裏付けがなければ語れない。

主張レベル（causation_claim）は次の3値のいずれか：

- `"descriptive"` — 記述。分布・水準を語る。関係は語らない。
- `"correlation_only"` — 関連。「関係が見られた」まで。因果の語は使わない。
- `"causal_evidence"` — 因果。識別戦略の成立と中核仮定の確認が条件。例：DID なら並行トレンド、マッチングなら「観測された交絡で条件付ければ処置は無視可能」。**手法を適用したこと自体は条件ではない**——マッチングが調整できるのは観測された交絡のみで、未観測交絡が残れば因果は言えない。自治体の観察データでは `correlation_only` に留まるのが多数派であり、`causal_evidence` は例外的。

軸1は**結果を見る前に**、設計の性質として決まる。結果が「有意」だから昇格することも、「有意でない」から降格することもない。

### 2-2. 軸2：結果の読み（finding_strength）

関連・効果の推定（Q2・Q3、Q5 のドライバー分析）には、**推定値と信頼区間**を、設計時に定めた「政策的に意味のある差」M（2-3節）と照らして、次の4値で読む：

- **`clear`（明確）** — 信頼区間が0を除外し、効果の大きさが政策的に意味のある水準。
- **`suggestive`（示唆的）** — 点推定の方向は一貫しているが、信頼区間が0を含む。「◯◯の可能性が示唆されるが、確証は弱い」と語る資格がある帯。
- **`inconclusive`（判断不能）** — 信頼区間が広く、意味のある正の効果も負の効果も排除できない。「このデータでは判断できない」。**効果がないという意味ではない。**
- **`null_compatible`（実質ゼロと整合）** — 信頼区間が狭く、±M の範囲にほぼ収まる。「効果があるとしても小さい」。**これは行動可能な発見である**（効いていない施策の見直しは立派な政策判断材料）。

M が設定できない案件では `null_compatible` は使えない（ゼロ近傍と言うには基準が要る）。その場合は効果量を併記した上で clear / suggestive / inconclusive の3値で読む。判定規準は機械的に近い形で定めているが、最終的な語の選択は分析者の責任であり、根拠（推定値・区間・M）を必ず添える。

### 2-3. 「政策的に意味のある差」M は設計時に決める

可能な案件では、分析タスクごとに **M**（例：「地区間で進学意向が5ポイント以上違えば施策配分の判断に影響する」）を分析の設計段階で、**根拠とともに定めて固定する**（事前登録の考え方）。**結果を見た後に M を動かしてはならない。** 事前に固定するからこそ、軸2の判定が「都合のよい後付け」から守られる。

M は「あってほしい差」や政策目標ではなく、**「それを超えたら政策判断が変わる」最小の差**である。予算判断の閾値、先行・類似施策で観測された効果量、制度上の区切りなど、**意思決定に結びつく参照点に係留**して定め、根拠を明記する。係留できる参照点がない場合は、無理に M を置かず、軸2は3値で運用する（2-2節）。M を置けない案件は多い。それは失敗ではなく既定の運用であり、根拠のない M をでっち上げる方が、置かないことよりも誠実性を損なう。

### 2-4. 表現ルール（軸1 × 軸2）

`descriptive` は軸2の対象外（分布・水準を正確に記すのみ）。関連・効果は下表で語る：

| 軸1＼軸2 | clear | suggestive | inconclusive | null_compatible |
|---|---|---|---|---|
| **correlation_only** | 「AとBに明確な関連（r=0.42, 95%CI [0.28, 0.54]）」 | 「関連が示唆されるが、確証は弱い」 | 「関連の有無はこのデータでは判断できない」 | 「政策的に意味のある関連があるとしても小さい」 |
| **causal_evidence** | 「施策はXを約◯pt押し上げたと考えられる（DID推定、並行トレンド確認済み）」 | 「押し上げた可能性が示唆されるが、確証は弱い（識別仮定の検証が限定的）」 | 「効果の有無はこのデータでは判断できない」 | 「効果があるとしても±◯ptの範囲で小さい」 |

**絶対の禁止（軸に関わらず）：**
1. 識別戦略の裏付けなく因果の語（「影響した」「引き起こした」「〜のせいで」）を使う。
2. `inconclusive` を「効果がない」と語る（判断不能とゼロの混同）。
3. `suggestive` を断定形で語る。
4. 結果を見た後に M や主張の軸を動かす。

### 2-5. 「もっと何か言えないか」への応答空間

分析の依頼者や政策決定者は、しばしば「住民や議会に一行で伝わる、数字で裏付けられたメッセージ」を求める。その要求自体は正当である。**「もっと何か言えないか」という圧力への正当な応答は、次の3つに限る**：

1. **示唆的所見を不確実性つきで言う** — `suggestive` の正規語彙で。「効果はプラスの可能性があるが、まだ確証はない」も、伝わる一行になる。
2. **精密なゼロを積極的に報告する** — `null_compatible` は「この施策はこのままでは効いていない」という行動可能な知見。隠さず主役にしてよい。
3. **証拠のアップグレード経路を示す** — 「統制群を置けば／期間を延ばせば／◯◯を調査項目に加えれば、次は◯◯が言える」。次の調査・データ設計の提案として返す。

**禁じ手は1つ：結果を見た後のスライス探索。** 納得のいく数字が出るまでサブグループを切り続ければ、偶然の変動が「発見」に化ける（いわゆる forking paths）。結果を見た後に追加した分析はすべて「探索的」と明記する。

## 3. 問いの型別カタログ

各型に「主な手法／設計時に確認すること／ガード／主張の上限」を定める。

### Q1 記述する

**主な手法：** 度数分布表（件数＋%）、連続変数の要約（平均・中央値・SD・最小/最大・N）、推移の可視化（時系列プロット）。自由記述の質的整理（カテゴリ化・代表的な声の抽出。恣意的な選別を避け、選定基準を明記する）。

**設計時に確認：** 母集団は誰か（全数か、抽出か、自発回答か）。回収率。誰の声が入っていないか。

**ガード：** N < 30 のサブグループには注記。

**主張の上限：** `descriptive`。

### Q2 関連を探る

**主な手法：**

クロス集計＋χ²＋Cramér's V：
```python
raw = pd.crosstab(df[row_var], df[col_var])                      # 実数の表（検定・効果量用）
pct = pd.crosstab(df[row_var], df[col_var], normalize='index')   # 行%（報告用）
chi2, p, dof, expected = scipy.stats.chi2_contingency(raw)
n = raw.values.sum()          # 必ず実数の表から取る（正規化後の表から取ると誤る）
cramers_v = np.sqrt(chi2 / (n * (min(raw.shape) - 1)))
# 期待度数の確認：8割以上のセルで expected >= 5、全セルで >= 1
```
報告：観測数、行%、χ²、p 値、Cramér's V。期待度数の条件を割る場合はカテゴリの統合、または（2×2 中心に）Fisher の正確検定を検討し、その旨を注記。

群間比較：2群は **Welch の t 検定**を既定（等分散を仮定しない）、順序尺度・非正規なら Mann–Whitney。3群以上は ANOVA / Kruskal–Wallis、事後比較には多重比較補正（Holm 等）。いずれも**効果量（Cohen's d、差そのものと CI）を併記**。

相関：連続変数は **Pearson r**。係数の算出に分布の仮定は要らず、正規性が関わるのは有意性検定・信頼区間の側（中規模以上の N では概ね頑健）。係数は外れ値に脆いので、算出前に散布図で線形性と外れ値を確認する。順序変数（リッカート）は **Spearman ρ** を既定（等間隔性を仮定しない。より原理的には polychoric 相関も選択肢）。

関連の整理としての回帰：少数変数の重回帰／ロジスティック回帰。順序尺度のアウトカムには順序ロジットが原理的（N が許す場合のみ。比例オッズ仮定に留意。無理ならカテゴリ統合か記述に留める）。VIF > 10 は多重共線性の警告。標準化係数と生係数の両方を報告。

**設計時に確認：** 変数の測定水準（名義／順序／連続）。欠測の量と偏り。**探索モードか確認モードか**——多数の関連を眺める探索なら「探索的」と明記、少数の事前指定仮説の確認なら多重比較補正（Holm 等）。

**ガード：** 期待度数（クロス集計）。EPV ≥ 10（ロジスティック：変数あたりイベント数）。線形回帰は説明変数1つあたり観測10〜20を目安。多重比較（上記）。

**主張の上限：** `correlation_only`。

### Q3 因果効果を推定する

**前提：** まず「このデータで識別戦略が構想できるか」を問う。構想できなければ、この問いは Q2（関連＋交絡の限界の明記）として扱う。データの状況で設計を引く：

| データの状況 | 設計 | 備考 |
|---|---|---|
| 統制群あり・処置前に複数期間 | **DID** | 並行トレンドを図＋（可能なら）イベントスタディ／プラセボで確認。処置前1点ずつの 2×2 では並行トレンドは検証不能 |
| 統制群なし・長い時系列 | **分割時系列（ITS）** | 前後に十分な時点数（目安：各8時点以上）。同時期の他の変化（歴史効果）・季節性に注意 |
| 統制群なし・前後1点ずつ | 因果設計は**不成立** | 前後比較は記述／関連として報告（`correlation_only`、交絡を明記） |
| 横断・処置/非処置の比較 | 回帰調整・マッチング・**傾向スコア**（IPW 含む） | 調整できるのは**観測された**交絡のみ。overlap（共通サポート）を確認。未観測交絡の限界を必ず明記。小 N では非現実的なことが多い |

回帰の実装ノート（時系列）：
```python
import statsmodels.formula.api as smf
model = smf.ols("y ~ x_event + C(weekday) + C(month) + weather_dummy", data=df)
res = model.fit(cov_type='HAC', cov_kwds={'maxlags': L})  # 自己相関に頑健なSE（Newey–West）
# L の目安：floor(4 * (T/100)**(2/9))
```
報告：係数・SE・t 値・p 値・95%CI・R²・N。DID は交差項（treated × post）の係数・SE・CI。

**頑健性メニュー（軽量）：** 識別仮定が完全に確認できないとき、即降格ではなく**崩れ方を確かめてから判断**する。メニュー：プラセボ処置日（偽の介入日で効果が出ないこと）／統制群の入れ替え・leave-one-out／イベントスタディ図／影響しないはずのアウトカムでのプラセボ。通れば `causal_evidence` × `suggestive` の帯で報告する余地があり、通らなければ `correlation_only` に降格。**実行は必要最小限を選ぶ**（全部やる義務はない——それ自体が過剰分析になる）。

**設計時に確認：** 介入の時期と対象。比較しうる集団の有無。処置前の期間数。同時期に他に何が起きたか。

**主張の上限：** 条件を満たす場合のみ `causal_evidence`。満たさなければ `correlation_only`。

### Q4 予測・分類する

**用途：** どの層が◯◯しやすいかの探索（セグメント発見・優先順位付け）。

**主な手法：** 決定木（解釈可能性のため max_depth ≤ 4、乱数固定）。
```python
from sklearn.tree import DecisionTreeClassifier
from sklearn.model_selection import cross_val_score
dt = DecisionTreeClassifier(max_depth=4, random_state=42)
scores = cross_val_score(dt, X, y, cv=5)   # 交差検証で汎化を確認（小Nでは必須）
```
報告：交差検証の性能、特徴量重要度、樹形図。クラスが極端に不均衡な場合は精度（accuracy）だけでは誤解を招くことに注意。

**絶対の警告：変数重要度 ≠ 効果の大きさ ≠ 原因。** 重要度の高い変数を「◯◯が原因」と読み替えない（自治体分析で最もありがちな誤読）。予測性能は「予測できる」という主張であって、関連の強さでも因果でもない。

**ガード：** 小 N では単一木の重要度は不安定——結果は**探索的（仮説生成）**と必ず明記。交差検証なしの性能報告は不可。

**主張の上限：** `correlation_only`（予測性能の主張＋探索的仮説として書く。因果語は不可）。

### Q5 分解・モニタリングする

**主な手法：** KPI 因数分解（乗法または加法。ウォーターフォール／ツリー図で可視化）。モニタリング指標の設計（測定可能性・更新頻度・データ源を明記）。単純な趨勢の外挿（不確実性の幅を付す。これは機械的な外挿＝projection であり、予測ではないことを明記）。類似団体とのベンチマーク比較（外部データの取得を要することが多い）。

ドライバー分析（何が KPI を動かすか）は **Q2 として実施**する（多変量回帰なら Q2 のガードに従う）。

**設計時に確認：** KPI の定義と測定方法。分解の恒等式が成り立つか。目標値の根拠。

**主張の上限：** 分解の恒等式は `descriptive`。ドライバー分析は `correlation_only`。

## 4. 共通ガードと報告ルール

### 過剰分析の防止

生の N は便宜的な目安にすぎない。**本当の制約**：クロス集計は期待度数、ロジスティックは EPV ≥ 10、線形回帰は説明変数あたり観測 10〜20、サブグループ比較は各群の N、粒度の粗い結合変数は集団数（次項「粒度の異なるデータの結合」参照）。

素早い足切りの目安（補助）：

| N | 目安（できること） | 避ける |
|---|---|---|
| < 50 | 記述・クロス集計（期待度数を確認）・群あたり N≥20 なら2群比較 | 多変数回帰・決定木・クラスター分析 |
| 50〜150 | ＋相関分析・ごく少数変数の回帰 | 多変数ロジスティック・クラスター分析 |
| 150〜 | ＋少数変数の回帰・決定木（交差検証必須） | 深い木・多変数モデルの乱用 |

例：N=173 のアンケートに多変数ロジスティック回帰とクラスター分析を重ねる提案は、この意味で過剰である。この表は上限ではなく「超える手法には相応の理由が要る」ライン。区分の数値そのものは独立した数学的規準ではなく、上記の"本当の制約"を典型的な変数構成に当てはめて逆算した便宜値である。制約に共通する原理は一つ：手法の信頼性は生の N ではなく、その手法が実際に消費する単位で数えた情報量（セルあたりの期待度数、イベント数、推定パラメータあたりの観測数、集団数）で決まる。判定は常に本当の制約の側で行う。

### 粒度の異なるデータの結合

分析対象の個票に、より粗い粒度（市町村別・都道府県別など）の統計を結合する場合の規律。

**1. 粗い粒度の値は「文脈変数」である。** 個票に市町村別の値を付しても、増えるのは独立な観測ではなく文脈である。その変数の推論上の実効サンプルサイズは概ね集団数（結合先が7市町村なら実効N≈7）であり、個票NでSE・p値を計算すると過大に有意になる。少数クラスタ（目安：30未満、とくに10未満）では、その変数についての統計的検定は計画せず、記述・可視化・ベンチマーク比較に留める。検定する場合はクラスタ頑健SEを要するが、クラスタ数が少ないと頑健SE自体が信頼できない。設計段階で「この変数の推論は集団数ベース」という限界を明記する。

**2. 生態学的誤謬の禁止。** 集団単位で観察された関連を、個人単位の関連として解釈しない（「平均所得が高い町で定住意向が高い」から「所得が高い個人は定住意向が高い」は導けない）。報告の主語は集団に保つ（「〜の町では」）。

**3. 結合キーの妥当性。** 市町村の結合は名称一致ではなく標準コード（全国地方公共団体コード）を用いる。名称結合は表記揺れ（「ヶ／ケ」・旧字・同名自治体）で静かに失敗する。時間キーは年度／暦年のズレと調査基準日を確認する。対象期間が市町村合併・境界変更をまたぐ場合は、コード対応表の要否を確認する。

**4. 結合被覆率と欠損の偏り。** 結合後、外部変数が全行に付くとは限らない。被覆率（非欠損件数／総行数）を確認・報告し、繋がらなかった行に偏り（特定地域・特定属性の欠落）がないかを検討して限界として明記する。

**5. 公表統計の表章記号。** 記号の意味は統計ごとに凡例で確認し、無確認で一律に0や欠損へ変換しない。「X」（秘匿）・「…」（資料なし）は欠損として扱い、0と混同しない。「-」は「該当数字なし」を意味することが多く、文脈により実質0か除外かが分かれる（凡例と変数の性質で判断）。「△」は負値の表記のことがある。公表値の「0」は表章単位に満たない値の丸めであることがあり、真のゼロとは限らない。

### 推定と報告の共通ルール

- **点推定と信頼区間を主、p 値を従**とする。「有意／非有意」の二分で結論を書かない。
- 効果量を併記する（Cramér's V、Cohen's d、標準化係数、実質的な差）。
- 小 N・歪んだ分布・複雑な統計量の区間には**ブートストラップ CI**（percentile / BCa）も選択肢。
- 数値は過剰な桁を丸め、N を常に添える。

## 5. 統計的誠実性チェックリスト

- [ ] N をすべてのサブグループで報告し、N < 30 には注記を付けた
- [ ] 効果量を併記した
- [ ] 表現ルール（軸1×軸2）に従い、設計が支える以上の主張をしていない

- [ ] 粒度の粗い結合変数について、実効サンプルサイズ（集団数）の限界を明記した
