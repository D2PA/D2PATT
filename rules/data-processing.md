# データ処理のルール

データの読み込み・出力・マスキング・監査・外部データの扱いを定める。読むのは data-scientist（実装の全般）と data-analyst（マスキングと監査）。

---

## 1. 書く前の基本

### データの読み込み

| 形式 | ライブラリ | 注意 |
|------|-----------|------|
| CSV / TSV | `pd.read_csv()` | encoding は `utf-8-sig` → `cp932` の順（下記「文字コードの規約」） |
| Excel（単一シート） | `pd.read_excel()` | `engine='openpyxl'` を明示する |
| Excel（複数シート・複数ファイルの統合） | `pd.read_excel()` + `pd.concat()` | シート名・列名の不統一に注意。統合の後に重複を確かめる |
| Google Forms の CSV | `pd.read_csv()` | タイムスタンプ列は datetime に変換し、分析からは外す |

### 文字コードの規約（境界ファイルと内部ファイルの二階級制）

ファイルを二つに分けて扱う。**境界ファイル**（利用者由来の生入力と、外部の手動配置ファイル）と、**内部ファイル**（我々の道具と data-scientist が書いたもの）。前処理が正規化点で、そこから下流は全経路 UTF-8 に統一される。

- 境界ファイルは、`utf-8-sig` で厳格に読み、`UnicodeDecodeError` のときだけ `cp932` で厳格に読む。**試行順は変えない**——cp932 のバイト列はまず不正な UTF-8 になるので先に UTF-8 を試せば誤読しないが、逆順にすると UTF-8 のファイルが cp932 として「読めてしまい」、文字化けが黙って通る。両方失敗したら、`errors="replace"` 等で握り潰さず、平易な日本語で止める。文字コードの推測ライブラリ（chardet 等）は使わない。
- どの文字コードで読めたかは、監査結果の `source_encoding` に記録される（値は `"utf-8-sig"` か `"cp932"`）。前処理は生入力をこの値で読み、推測をやり直さない。
- 前処理の出力は常に UTF-8 で書く。内部ファイルの読み書きは UTF-8 固定で、フォールバックを入れない——自分たちが書いたファイルが cp932 で読める状況は異常であり、隠さず落とす。

### 複数ファイルの統合

日ごと・支所ごとに分かれた Excel を統合する場合：

1. 全ファイルを `glob` で列挙する
2. 各ファイルを読み、`source_file` 列を足してから `pd.concat()` する
3. 列名の揺れ（全角と半角、空白の有無）をそろえる
4. 統合の後に `df.duplicated()` で重複を確かめる

### 欠損値の処理方針

欠損の処理方法は勝手に決めず、方針を示して人間の確認を得る（例外：欠損率が 5% 未満で、分析対象外の列）。

| ケース | 示す選択肢 |
|--------|-----------|
| リッカート尺度の欠損 | 除外／最頻値で補完／「無回答」の区分として残す |
| 自由記述の欠損 | 除外（集計の対象外として記録） |
| 数値変数の欠損率が 20% 超 | 補完より除外を勧める。読者向けに「有効 N」を明記する |

### 出力の置き場

パスはすべて、受け取った絶対 `OUTPUT_DIR` の下に書く（相対パスは不可。案件フォルダの名前を自力で組み立てない。`CLAUDE.md` → 動かすときの約束）。

| 出力 | パス | 形式 |
|------|------|------|
| 図 | `<OUTPUT_DIR>/figures/<task名>.png` | PNG・300dpi |
| 集計テーブル | `<OUTPUT_DIR>/tables/<task名>.csv` | UTF-8 CSV |
| 分析ログ | `<OUTPUT_DIR>/analysis_log.md` | Markdown（プログラムか Bash で追記する。Write ツールは使わない） |
| 作業プログラム | `<OUTPUT_DIR>/scripts/<task名>.py` | Python |

### 日本語フォント（OS に依存させない）

```python
try:
    import japanize_matplotlib  # noqa: F401
except ImportError:
    import platform, matplotlib
    _fonts = {'Darwin': 'Hiragino Sans', 'Windows': 'Meiryo', 'Linux': 'IPAexGothic'}
    matplotlib.rcParams['font.family'] = _fonts.get(platform.system(), 'sans-serif')
```

特定 OS のフォント名を、ガードなしに直書きしない（他の OS で文字化けする）。

図における軸ラベル・凡例・表題なども全て日本語で書く。列名の英語の識別子（`settle_intent_ord` など）をそのまま出さない。表題が枠からはみ出す場合は、`fig.tight_layout()` を呼ぶか表題を短くするなどして対応する。

### 書き方の落とし穴（最初から正しく書いて、直しの回数を減らす）

- **型の混在。** 数値の列に、文字や NaN の混じった値を入れる前に、列を object 型に直してから入れる（`df[col] = df[col].astype(object)`）。
- **f-string の入れ子。** f-string の中に、書式指定や同じ引用符を入れ子にしない。値をいったん普通の変数に入れてから、単純に埋め込む。
- **文字コード。** CSV の読み書きは `encoding="utf-8-sig"`。スクリプトの冒頭に `sys.stdout.reconfigure(encoding="utf-8")` を入れ、Windows で日本語が化けないようにする。
- **列名。** 日本語の列名は記憶で打ち直さない。`df.columns.tolist()` に出た実物の文字列を、そのまま写して使う。

## 2. 生データのまとまりを出さない

データの中身をそのまま取り出す操作を、画面・成果物・ログに対して行わない。禁じるのは、行をまとまりとして書き出す操作である——`df.head()`・`df.tail()`・`df.sample()`・`print(df)`・`to_string()`・列や行を順に回して値を並べる出力。これは security_concern の値に依らず、常に守る。

一方、作業の途中で個々の値が現れることは禁じていない。データの問題を報告するために実例を一つ挙げる、プログラムが返したエラーの文言をそのまま伝える、自由記述の文章を読んで分類する——いずれも、その作業のために必要な範囲であれば行ってよい。

集計した値も対象ではない。該当が1件のマスの度数も、1件だけの群の平均・最小・最大も、そのまま出してよい。人数の多少を理由に集計値を伏せる処理は行わない。

迷ったときは、データを取り出すことが目的ならば行わない。作業を進めるために必要なものであれば許容する。

## 3. マスキングと監査

### 原則（security_concern で分岐）

個人情報の規律は、入口で人間が宣言する security_concern に従う（詳細は `CLAUDE.md` → 守るべき制約）。

- 懸念あり（true・既定）のとき：マスキング前のデータに `df.head()`・`df.tail()`・`print(df)` を実行しない。外に出すのは列名・型・集計の水準の情報のみ。マスキングは前処理の中で、すべての派生列を作った後に行う。
- 懸念なし（false）のとき：監査・マスキングは行わない（`pii_columns=[]`）。構造の把握は `profile_data.py` が担う。

### マスキングの手順

マスキングは `tools/mask_pii.py` で行う（data-analyst が、派生済み CSV に対して実行）。入力は派生済み CSV、出力は共有の `preprocessed_input.csv`。パスは受け取った絶対 OUTPUT_DIR を使う：

```bash
OUTPUT_DIR="<受け取った案件フォルダの output/ の絶対パス>"
bash "$LAYER_DIR/tools/run" mask_pii.py \
  --input "$OUTPUT_DIR/derived_input.csv" \
  --pii-columns "colA,colB" \
  --output "$OUTPUT_DIR/preprocessed_input.csv"
```

指定した列の各値は SHA-256 のハッシュに置き換わる。NaN は NaN のまま。実行後に自己検査が走り、不合格なら 0 以外の番号で止まる。出力先が既存ファイルなら `--force` が要る。

### データ監査（security_concern=true の案件のみ）

監査は、人間が個人情報の列を確定する前に、マスク前の元 CSV に対して行う（依頼は data-analyst を経由して届く）。個人情報らしき列の一次指摘は、列名・型・集計の水準から行う——値の中身を見ての最終確定は人間の仕事。返す AUDIT_JSON は集計の水準の情報だけ——行データ・`df.head()` は不可。

quality_issues に立てるフラグの基準：欠損が2割を超える列／想定外の型／重複行／ありえない範囲の値／個人情報らしき列（列名と型の水準まで——行の値は見ない）／自由記述らしき列（文字列型で、値がほぼ全件異なる、または長い文章が入っている列——列名と型・水準の情報から判断し、行の値は見ない）。平易な日本語で書く。

## 4. 外部データの扱い（結合と参照値）

外部オープンデータを手元データに**結合する**（`external_merges`）か、比較の基準として**参照する**（`external_references`）ときの実装知識。前処理の依頼にどちらも無ければ、本節は読まなくてよい。

### 読み込みの癖（公的データ特有）

- **文字コード**：外部の CSV も境界ファイルなので、1部の規約と同じ試行順（`utf-8-sig` → `cp932`）。公的統計の CSV は cp932 率が高い。読めない場合も行の値を印字して調べない（構造・列名・行数の確認まで）。
- **e-Stat 形式の癖**：表題・注記の前置行や多段ヘッダを持つことが多い。先頭数十行の構造を確かめて skiprows / header を決める。
- **統計表の記号**：「X」「-」「…」「△」等を一律に欠損として読まない。統計ごとに凡例を確かめ、記号別に対応を決める。目安——秘匿（「X」等）は欠損／「-」は凡例が「該当なし」なら実質ゼロのことが多い（件数系は 0、率系は欠損が妥当な場合が多い）／「△」は負値のことがある（数値化時に符号へ変換）／公表の「0」は丸めの結果でありうる。決めた対応は、コード内に対応表（定数）として明示し、黙って一律変換しない。
- **自治体コード**：全国地方公共団体コードは必ず文字列（dtype=str）で読み、5桁ゼロ埋め（`zfill(5)`）を保証する。int で読むと先頭の 0 が落ちて、結合が静かに失敗する。5桁と6桁（検査数字付き）の混在に注意し、結合の前に桁をそろえる。
- **時間キー**：年度と暦年のずれ、調査基準日を確かめてから結合キーにする。
- **xlsx**：`pandas.read_excel`（openpyxl）。シート名とヘッダ行を確かめる。

### 結合の規律（external_merges）

前処理の依頼に `external_merges` があるときは、同じ前処理タスクの中で、**すべての派生列を作った後に**結合する（結合キー自体が派生列のことがある）。各エントリを、与えられた順に：

1. `path` のファイルを読む——ローカルのファイルだけで、URL は受け取らない。読み方は上記「読み込みの癖」に従う。
2. `external_keys_actual` と `columns[].actual` に挙がった列だけを選び、各 `actual` を `rename_to`（依頼の意図名）に、**結合の前に**リネームする。下流の参照と `check_survival.py` の照合が、意図名を見るようにするため。
3. `df.merge(ext, how="left", left_on=local_keys, right_on=external_keys_actual, validate="m:1")` で結合する。**左結合は固定**——手元の行を落とさない。繋がらなかった行は NaN のまま残す（NaN の数が被覆率の信号で、下流の道具が結合後のデータから機械的に数える。自己申告の欄は作らない）。`validate="m:1"` は必須で、外部側にキーの重複があると MergeError が出る。そのときは出典名とキーを挙げてタスクの失敗として報告する。黙って重複を落とさない。`validate` を外して再試行しない。
4. 結合の後、不要になった外部側のキー列を落とす。

外部ファイルも、生の調査データと同じ「集計だけ」の規則の下にある——行の値を画面に出さない。返す `PREPROCESS_JSON` の形は変わらない（リネーム済みの外部列は `columns` に自然に含まれる）。

### 参照値（external_references と reference_values.json）

前処理の依頼に `external_references` があるとき、その出典は手元データに**結合しない**——分析を読むための比較値（全国・都道府県などの集計値）を供給する。抽出は**前処理で一度だけ**行う。全タスクが同じ数値を同じファイルから読み、各タスクが導き直さないようにするため。

各エントリについて：

1. `path` のファイルを読む（ローカルだけ・URL は受け取らない）。文字コード・ヘッダ・型の扱いは結合と同じ注意を払う。
2. `variables_to_use` に名指された変数**だけ**を、集計値として抽出する。公表統計でも「集計だけ」の規則は同じで、行の水準の値を印字も保存もしない。
3. その数値を読む人が知っておくべき留保——定義のずれ、出典の表の注記、構成要素から計算し直した値——を `notes` に記録する。黙って「整えた」基準値は、印を付けたものより悪い。

集めた値を `<OUTPUT_DIR>/reference_values.json` に書く。形は `agents_ICD/schemas/reference-values.json` が定める。

基準値が自然に内訳を持つときは、値を小さなオブジェクトにしてよい（例 `{"20代": 14.1, "30代": 11.8}`）。小さく、集計の水準に保つ。書いた絶対パスを `reference_values_path` として `PREPROCESS_JSON` に足す（`external_references` が無かったときは付けない）。

**読み方（分析タスクの側）。** タスクの `external_refs` に名前があり、`REFERENCE_VALUES:` を受け取ったときだけ、このファイルを読む。読むのは**自分のタスクの `external_refs` が名指すエントリだけ**。

```python
import json
with open("<REFERENCE_VALUES>", encoding="utf-8") as fh:
    refs = json.load(fh)
benchmark = refs["<external_refs が名指す source_name>"]   # values / granularity_and_period / sha256
```

比較値としてのみ使い、`df` の行として扱わない。基準値が結果に届くときは、出典を一緒に運ぶ（`source_name` と `granularity_and_period` を `key_finding` / `interpretation_note` に入れる）。時点と出所の無い数値は、下流で使えない。
